# 第 33 章 附件、溢出与通用存储

> 会话之外的持久字节


> 会话日志存事件，但产品还需要存**二进制**（用户上传的图片）、**超大文本**（工具结果溢出）与**普通领域数据**（工作区实体等）。三个缝各管一摊。

## 附件缝（ctx.attachments）

**职责**：持久二进制附件的身份、校验与内容寻址存储。

```text
用户上传图片 ──► Host 先提交附件（内容寻址）──► 再落会话事件
                     │
消费时：provider 适配器把授权的持久引用解析为 provider 原生内容
       （llm-deepseek / llm-pi-ai 都消费 ctx.attachments）
```

设计要点：

- **先附件后事件**：Host 在会话事件**之前**提交被接受的图片——引用永远指向已存在的字节。
- **内容寻址**：`attachment-local` 实现本地内容寻址存储；引用是持久身份，不随会话重生。
- **授权解析**：只有被授权的持久引用才会被适配器解析为模型可见内容。
- 消费者：`api-session-controller`（上传面）、`tool-fs`（模型读附件）、两个 LLM 适配器（多模态输入）。

## 溢出缝（ctx.spillStore）

**职责**：工具结果文本太大时的降级存储——**把超大工具文本存起来，返回一个模型可见的定位符 + 取回提示**。

```text
tool 结果超过输出上限
   │ tools/post-execute（spill-policy 是决策消费者）
   ▼
溢出正文 → spill 后端（spill-local 本地实现）
模型看到 → 定位符 + 取回提示（而非被截断的正文）
需要时 → 模型用取回工具按定位符读回片段
```

- `spill-policy` 拥有"何时溢出"的策略，挂在 `tools/post-execute`——策略与机制分离。
- 模型面对的是稳定的定位符词汇，不是实现细节。
- 与 PTC 的输出上限管线协同：只有外层 `run_code` 的日志/结果跨过可配置输出上限与模型可见的溢出管线。

## 通用存储枢纽（ctx.storage）

**职责**：非会话数据的 KV 存储枢纽 + 领域表单。

```text
多个后端按名字并排注册（storage-json / storage-sqlite）
        │
数据表单（domain 优先）挂在枢纽上
        │ 把类型化操作翻译成不透明 KV 单元原语
        ▼
ctx.storageDomain —— 等待每个配置的后端就绪，
然后把领域表单发布为一个生命周期绑定的类型化持久状态服务
        │
        ▼
消费者：workspace 实体注册表等
```

- **多后端并排**：按名字注册，不是互斥单选。
- **领域优先的数据表单**：消费者写类型化操作，表单层翻译成 KV 原语——后端只承诺不透明单元。
- `ctx.storageDomain` 保证"每个配置的后端都就绪后才发布"——半初始化状态不可见。

## 三缝对照

| | attachments | spill | storage |
|---|---|---|---|
| 存什么 | 二进制附件 | 超大工具文本 | 任意领域数据 |
| 寻址 | 内容寻址持久身份 | 定位符 + 取回提示 | 命名 KV 单元 |
| 消费者 | LLM 适配器、tool-fs、上传面 | tool 结果管线 | workspace 等领域服务 |
| 后端 | attachment-local | spill-local | storage-json / storage-sqlite |
| 特殊纪律 | 先提交后引用；授权才解析 | 策略在 post-execute，模型只见定位符 | 全后端就绪才发布领域表单 |

## 会话标题（session-title）顺带一提

同属持久化家族的 `ctx.sessionTitle` 拥有确定性回退、最新标题折叠，以及**唯一**的可选异步 provider 注册位——两个交付实现（`session-title-first-prompt-llm`、experimental 的 all-prompts 版本）证明了"sole provider"约束：标题生成只允许一个提供者。

## 设计启发

1. **按数据形态分缝**，不按存储技术分缝：字节/超大文本/领域数据各有各的访问语义，强行统一成一个"文件 API"会让每一方都别扭。
2. **引用先行**：附件先提交后引用、溢出先定位后取回——数据大体量永远不进事件日志，日志只存指针。
3. **策略消费者模式**：spill-policy 展示了"机制在缝里，策略在 post-execute 监听器"的分工——换策略不改存储。
